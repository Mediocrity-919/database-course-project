# 问笺 · 数据库课程项目第二阶段（v2）

本分支是在第一阶段问卷系统上进行的**需求变更与增量扩展**。第二阶段的重点是把原来仅属于某份问卷的题目，扩展为可以独立保存、共享、保留历史并跨问卷统计的常用题，同时继续使用原来的账号、问卷发布快照、答卷和填写流程。下文重点说明相对一期改变了什么，再给出环境、升级、启动与验收方法。

| 分支 | 内容 |
| --- | --- |
| [main](https://github.com/Mediocrity-919/database-course-project/tree/main) | 第一阶段成果 |
| [v2](https://github.com/Mediocrity-919/database-course-project/tree/v2) | 第二阶段需求变更、代码与测试；本README说明此版本 |

## 功能概览：新增能力与保留能力

题库、题目共享、题目版本及跨卷统计为二期新增。账号、问卷生命周期、跳转、填写、分享和问卷内统计为一期延续能力，不重复计为二期新增。

- 注册登录：用户名不区分大小写且唯一；新密码为8～128字符，必须包含大写、小写字母和数字，页面逐项提示。
- 问卷设计：单选、多选、文本、数字四类题目；必答、选择数量、文本长度、数字范围及整数校验；可配置条件跳转。
- 发布填写：不可变发布快照、截止时间、URL/二维码分享、填写草稿恢复、匿名与重复填写策略、原答卷修改及聚合统计。填写者需要登录，匿名表示向问卷创建者隐藏账号身份。
- 题库与共享：保存常用题、管理题库归属、按用户名共享；同一道题可以用于多份问卷。
- 版本管理：从任意历史版派生、查看来源、恢复旧内容为新版本；已发布问卷和旧答案保持原样。
- 使用与统计：反查引用问卷；统计单个版本或同题型版本合计。改名选项分开显示，外部问卷须授权才贡献汇总，外部文本原文不共享。

## 技术与数据结构

前端为React、TypeScript和Vite，后端为Node.js、Express和MongoDB官方驱动，共享模块统一校验与跳转规则。业务数据保存在MongoDB，不使用关系数据库或现成问卷框架。

| 集合 | 职责 |
| --- | --- |
| `users` / `sessions` | 账号与登录会话 |
| `surveys` / `survey_versions` | 问卷入口、草稿及不可变发布快照 |
| `responses` | 独立答卷、填写进度与修改草稿 |
| `question_banks` | 题库名称、说明及所有者 |
| `question_families` | 题目系列、共享名单、题库归属及最新版本指针 |
| `question_versions` | 不可变内容、版本号、父版本及恢复来源 |

题库复用采用“系列—版本—问卷内快照”：问卷中的`source`绑定固定版本，填写不读取题库最新版。新字段均为可选，旧问卷不需要回填。设计依据、索引与事务见[数据库设计](docs/database-design.md)和[第二阶段设计](docs/stage2-design.md)。

## 一期到二期：八项需求的具体变化

一期对比基线为 main 的 `cd7e6d8`。一期题目嵌在问卷定义中，发布时生成不可变快照，适合整卷编辑与填写；但多个副本没有共同身份，无法可靠追踪共享、版本和跨卷答案。按标题合并会混淆同名题，直接读取一份可变题目又会改变旧问卷的含义，因此二期增加题目身份和不可变版本，保留原问卷、发布快照和答卷主链路。

| 新需求 | 一期做法或不足 | 二期实现 | 页面入口 |
| --- | --- | --- | --- |
| 保存常用题、重复使用 | 题目仅属于某份问卷 | 独立保存系列与版本，可导入多个问卷 | 我的题库、新建常用题、从题库选题 |
| 分享给其他用户 | 无题目使用授权 | 按系列共享全部版本，双方可用；接收者可另存自己的系列 | 共享与题库归属 |
| 改题不影响旧问卷 | 有问卷快照，但无可复用题的更新规则 | 题库版本只追加，问卷使用固定版本及完整内容快照 | 派生新版、发布后查旧答案 |
| 记录历史和恢复 | 没有独立题目的版本链 | 记录父版本及恢复来源，恢复也生成新版本 | 版本历史、查看版本内容与来源 |
| 不同版本并存 | 副本没有明确的系列关系 | 从任意旧版派生，A选v1、B选v2 | 选择固定版本 |
| 查询使用与选择修改方式 | 无法按题目身份反查引用 | 查询草稿和发布快照；生成新版本或解除关联只改本卷 | 查看使用与统计、编辑器修改入口 |
| 管理题库 | 无独立题库分类 | 名称/说明、系列多题库归属、筛选；新版沿用归属 | 题库管理、筛选题库 |
| 单题跨问卷统计 | 只统计某份问卷内的题 | 按来源定位各卷实例，支持单版本和同系列同题型版本合计 | 仅此版本、全部版本合计 |

“不创建题库新版本”的修改方式是解除关联成为本卷独立题。已经保存的题库内容不原地覆盖，已发布问卷需要复制为新草稿后再修改。

## 数据结构具体如何变化

### 原五集合的保留与扩展

| 集合/字段 | 一期 | 二期变化及原因 |
| --- | --- | --- |
| users、sessions | 账号、会话和所有权隔离 | 继续使用；共享引用已有用户，不新建账号体系 |
| surveys | 问卷入口、草稿、创建者、状态及公开标识 | 主结构保留，草稿定义中可增加来源与汇总授权 |
| survey_versions | 冻结完整问卷定义 | 继续保存快照，其中可含来源；填写不动态跟随题库最新版 |
| responses | 绑定问卷发布版本、按本卷实例保存答案 | 结构和提交方式保留；通过快照解释跨卷答案，无须改写旧答卷 |
| question_banks | 无 | 新增题库名称、说明、所有者、修订号与时间 |
| question_families | 无 | 新增题目身份、作者、共享、归属、最新版本指针和版本计数 |
| question_versions | 无 | 新增不可变内容、版本号、父版本、恢复来源、作者和时间 |
| question.source | 无 | 可选 `{familyId, versionId}`，支持来源核验、引用查询及聚合 |
| settings.shareLibraryStatistics | 无 | 可选、默认不授权；把题目使用权与外部问卷统计权限分开 |

新增字段可选，旧题缺少source仍合法，不按相同标题自动并入某个系列。schemaVersion=1表示集合自身结构版本，不是课程阶段号。

### 为什么使用“系列—版本—问卷内快照”

```text
题目系列 F：作者、共享、分类
  ├─ v1：年龄，整数，0～120
  │    ├─ 问卷 A 的实例 qA → A 的发布快照 → A 的答卷
  │    └─ 问卷 B 的实例 qB → B 的发布快照 → B 的答卷
  └─ v2：年龄，整数，0～100
       └─ 问卷 C 的实例 qC → C 的发布快照 → C 的答卷
```

familyId回答“是不是同一道题”，versionId回答“哪次内容”，实例UUID回答“这份问卷中的哪道题”。导入时新建实例UUID，保留原版本的选项ID，答卷仍使用本卷实例。latestVersionId只用于展示，不会让A/B自动升级。

权限与归属会变化、版本内容需要冻结，因此拆开保存；版本不断增加，不放进系列的无限数组。问卷继续嵌入完整题目，填写时一次读取快照；来源引用保留可追踪性。重复内容是有校验约束的冗余，保存和发布时必须与来源版本一致。

### 新增约束、索引与事务

- 八集合均使用strict/error validator。常用题归一为order=1、无source、无本卷跳转规则、默认下一题；题型、必答、选项和校验仍复用一期结构。
- 保存/发布时比较题干、说明、题型、选项、必答和校验等核心内容，拒绝保留source却篡改内容；跨集合归属和授权由后端检查。
- 新增7个业务索引，合计18个，不含MongoDB默认_id索引：题库/系列查询、共享和归属数组查询、系列内版本号唯一、草稿/发布快照来源查询。
- 系列与首版、后续版本与最新指针使用MongoDB事务。revision乐观锁配合`(familyId, versionNumber)`唯一索引，防止重复编号、覆盖和孤立版本。
- 同卷不能重复同一版本，不同版本可以并存。系列最多归入20个本人题库、共享给50个用户，数组大小有界。

### 从题库选题

在题库页创建常用题，或把草稿独立题“存为常用题”；后者保存题库副本，当前题仍独立，需要主动从题库导入才建立关联。新建问卷时点击“从题库选题”，选系列和“使用v1/v2…”，导入后核心内容锁定，本卷顺序和跳转可单独配置。这里不自动扫描所有旧问卷，也不按标题关联旧题。

### 派生、恢复、替换及独立修改

| 操作 | 生成结果 | 原有问卷 |
| --- | --- | --- |
| v1派生v2，又从v1派生v3 | v2/v3的父版本均为v1，可以并存 | 继续使用原版 |
| 当前最新v3时恢复v1 | 追加v4，parent=v3、restoredFrom=v1 | 不回退快照、不删除v2/v3 |
| 作者“保存为新版本并替换” | 本系列追加版本，替换当前草稿的题，再保存问卷 | 其他问卷不自动更新 |
| 接收者修改共享题 | 另存为自己的新系列并记录来源，替换当前题 | 原系列不变 |
| “解除关联并编辑副本” | 新UUID、移除source、只改本卷独立题 | 不计入原系列统计 |

替换版本会重置本题跳转，并将其他题指向旧实例的跳转改指新实例；解除关联保留本卷内容和跳转。常用题不保存跨问卷跳转目标，因为目标属于具体问卷的实例ID。

### 共享与统计授权分开

共享允许接收者使用整个系列的历史版本，不授予修改原系列的权利；只有作者可改原系列和授权。撤销后禁止新导入，已保存的问卷继续使用原版，仍要通过核心内容校验。

使用清单仅给本人问卷提供管理链接；作者查看未授权外部引用时以匿名名称占位。外部问卷创建者需在发布前主动开启shareLibraryStatistics，才向题目作者贡献名称和汇总。共享题目不会自动共享账号、参与者标识、完整答卷或外部文本原文。

## 跨问卷统计相对一期增加了什么

一期按“问卷+题目实例”统计；二期先按来源版本查发布快照，再将`(surveyVersionId, questionId)`映射到答案，最后在MongoDB聚合。没有额外维护容易过期的统计集合。

| 口径 | 二期规则 |
| --- | --- |
| 仅此版本 | scope=version，只计算确切版本 |
| 全部版本合计 | scope=family，合计同系列同题型版本，并逐版列出份数 |
| 有效答案 | submitted主答案；草稿、editDraft、跳过题和空可选题不计入分母 |
| 数字 | 份数、平均、最小/最大、自动分桶分布，无数据均值为null |
| 选择题 | 先按历史版本解释答案，选项ID与文字均相同才合并；改名选项单列 |
| 文本 | 有效数量及本人原文分页；外部文本只贡献数量 |
| 人数 | 跨卷按答案份数，不宣称将不同问卷的participantKey去重成人数 |

A/B用v1答20/40，C用v2答30：v1为2份、平均30，全部版本为3份、平均30。不能直接对每卷均值做不加权平均；题意或单位变化需使用单版本统计，系统不自动判断语义等价。

## 兼容性与旧功能如何验证

升级先备份，再增补三个集合、可选字段、validator和索引；db:init不清空原集合。旧问卷、发布快照与答卷不回填。前端锁定只是交互提示，后端保存/发布仍独立验证来源，不能仅靠禁用输入框保证历史一致。

一期94项单元/API和19条浏览器流程保留；二期增加34项单元/API/核查/脚本及7条浏览器流程。升级前后原记录哈希比对、只读核验、原功能回归共同验证兼容性；已有功能包括跳转、原答卷修改、重复填写、匿名与二维码。Git分支不隔离数据库，v2能读旧文档不代表main能编辑二期结构，两期同时演示需使用不同数据库。

## 环境要求

- 推荐Node.js 24、npm 11、MongoDB 8；`package.json`要求Node.js ≥22.12，依赖版本以锁文件为准。二期未新增npm包或外部服务，仍使用MongoDB，不引入关系数据库。
- MongoDB必须以副本集运行以支持事务。本地脚本启动`survey-rs`单节点副本集，端口27018，数据放在`.local/mongo-rs`，不修改已有27017实例。
- 浏览器测试默认使用Windows已安装的Chrome；没有Chrome时可运行`npx playwright install chromium`。
- 下列命令在Windows PowerShell、v2分支的项目根目录执行；其他终端可将`npm.cmd`写为`npm`，一键验收脚本需要Windows PowerShell。

## 首次启动

```powershell
npm.cmd ci
npm.cmd run setup
```

`setup`仅在`.env`不存在时创建配置并生成随机密钥；已有配置不会覆盖。若`mongod`不在PATH且未安装于`D:\mongodb\bin\mongod.exe`，先在`.env`填写`MONGOD_PATH`的实际路径。

新环境继续执行：

```powershell
npm.cmd run db:start
npm.cmd run db:init
npm.cmd run build
npm.cmd start
```

打开[本地网站](http://localhost:3000)，自行注册账号。Express同时提供构建后的前端和`/api/v1`接口，无需另开前端进程。修改源码后需要重新构建并重启服务。

### 从第一阶段升级

已有数据时，保留原`.env`和数据库，在v2代码下先备份，再增量初始化：

```powershell
npm.cmd run db:start
npm.cmd run db:backup
npm.cmd run db:init
npm.cmd run db:verify -- --baseline latest
npm.cmd run build
npm.cmd start
```

逐条执行，前一步失败时先排查，不继续初始化。备份包含敏感数据，仅保存在被忽略的`.local/backups`。不要更换`PARTICIPANT_HMAC_KEY`，它影响历史参与者标识。Git分支不隔离MongoDB数据，main不理解二期字段；同时展示两期应分别使用不同数据库。

### 开发模式

```powershell
npm.cmd run dev
```

访问[开发页面](http://localhost:5173)，Vite将API请求代理到3000。若希望分享页也使用热更新前端，将`.env`中的`PUBLIC_BASE_URL`设为`http://localhost:5173`并重启后端。使用构建后的完整网站时采用`http://localhost:3000`；两种方式均需把实际来源加入APP_ORIGIN。

## 主要配置与局域网访问

| `.env`配置 | 说明 |
| --- | --- |
| `MONGODB_URI` | 开发库连接，模板使用`questionnaire_stage1`；二期沿用库名 |
| `MONGODB_TEST_URI` | 独立测试库`questionnaire_test`，测试会清理其中数据 |
| `HOST` / `PORT` | 当前本机环境监听`127.0.0.1:3000` |
| `APP_ORIGIN` | 允许注册、登录和修改请求的网页来源，多个地址用逗号分隔 |
| `PUBLIC_BASE_URL` | 当前为`http://localhost:3000`，决定URL与二维码的入口 |
| `COOKIE_SECURE` | 本地HTTP为`false`，HTTPS为`true` |
| `PARTICIPANT_HMAC_KEY` | setup生成并持久保存的密钥，只放在后端配置中 |

局域网演示使用构建后的3000入口：将`HOST`设为`0.0.0.0`，`PUBLIC_BASE_URL`设为`http://电脑当前局域网IP:3000`，并把该完整地址加入`APP_ORIGIN`，HTTP下保持`COOKIE_SECURE=false`。重启服务并重新生成分享二维码。

手机与电脑需处于可互访的同一局域网，系统防火墙允许该服务入站；MongoDB仍只监听回环地址。IP变化需更新配置，电脑关机或服务停止后无法访问。公网及Cloudflare方案见[部署说明](docs/deployment.md)，当前未完成公网部署。

## 第二阶段操作示例

1. 打开“我的题库”，创建“基本资料”题库和数字题“年龄（周岁）”，设置0～120及整数要求，保存并设置题库归属。
2. 建立两份问卷，点击“从题库选题”并选择v1。题目核心内容锁定，本卷跳转单独配置；发布后分别填写20和40。
3. 在题库查看使用与统计，应显示两份有效回答、平均30。按用户名共享给另一个账号后，对方可导入或另存自己的题目。
4. 从v1创建v2，原问卷继续使用v1。草稿中可选择“保存为题库新版本并替换”，或“解除关联并编辑副本”只改本卷。恢复v1会追加新版本，历史不覆盖。
5. 在“仅此版本”和“全部版本合计”间切换。合计只纳入同题型版本；选项ID与文字均相同才合并。题意或数字单位变化时应使用单版本统计。

共享题目不等于共享答卷。默认只统计本人问卷，题目作者还可统计明确允许汇总的外部问卷；文本原文仅来自本人问卷。跨卷按有效回答份数统计，不宣称去重人数。
