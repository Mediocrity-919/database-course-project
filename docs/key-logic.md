# 关键逻辑

## 第二阶段执行路径

独立题：Library页面→共享libraryContent校验与上下文清理→LibraryService事务写系列和v1。修改/恢复：读取所选版本→验证作者和revision→插入新版本并更新系列指针；任何旧版都不覆盖。恢复保存双重来源parentVersionId/restoredFromVersionId，便于区分“从哪里修改”和“恢复了什么内容”。

复用：LibraryPicker按题库选系列及指定版本→import接口检查授权、产生新实例UUID→Editor复制到definition并锁定核心字段→save/publish再次验证来源内容→问卷发布快照→答卷绑定surveyVersionId。实例的跳转不存回题库；替换题目时重置自身规则，并将其他题目指向旧实例的跳转改指新实例。解除关联保留本卷内容和跳转，换新UUID且去掉source。

共享：原作者维护用户名名单和本人题库归属，接收者可使用/另存，但不能编辑原系列。撤销只阻止新引用，不影响已经保存的问卷；引用核心仍需与历史版本完全一致。题目共享权限和统计授权分开，后者由问卷发布设置控制，默认不开放。

跨问卷：LibraryService.stats先按来源版本找发布快照并做权限过滤，再将snapshot+实例ID映射到提交答案，使用facet算回答数、选项频数、数字分布和本人文本分页。默认仅统计所选版本，可主动选择同系列同题型版本合计；选项ID和文字均相同才合并。旧题未标source不纳入，不按相同标题猜测关联、不跨卷比较participantKey。

前端入口为/library；桌面侧栏及手机导航均可访问。版本详情显示完整内容、来源、使用情况与当前选中版本的统计。新旧历史均能选用；题库归属基于系列，所以创建新版本自动出现在原题库中。

## 跳转与校验

题目logic存储first_match规则列表和默认动作。规则按priority升序执行，单选eq、多选contains_any/contains_all/equals_set、数字eq/gt/gte/lt/lte/between。动作next、goto后续题、end。默认动作也须合法，最后一题next等于end。

规则和选项保存在MongoDB定义中，条件不写死在具体问卷代码。共享函数由浏览器和后端共同使用，后端提交时重新重放完整路径。被跳过的必答题不验证；实际经过的必答题必须有值。可选空题可跳过，一旦作答仍要满足范围。

数字0与空输入区分，必须有限；整数使用安全整数范围。文本trim、换行规范化后按Unicode码点计数。多选重复选项拒绝，规范化按ID排序，保证提交摘要稳定。

文本答案使用共享normalizeTextAnswer与textAnswerLength：前端计数、请求schema的2000码点上限、每题业务min/max采用相同口径。文本框移除按UTF-16计数的原生maxLength，超限不截断，校验后提示修正；空白和CRLF按规范化结果计数。😀、𠀀各为1码点，组合表情不保证只算1码点。数据库仍保存规范化文本，已有maxLength:2000约束经真实MongoDB测试一致，无需迁移。

返回前题修改答案后，前端重算可达路径并清除旧分支。后端拒绝不可达的残留答案，避免隐藏题污染统计。前端通过访问历史实现上一题。预览不创建答卷。

上一题与下一题都会等待有效答案保存成功后切换。前端只向草稿接口发送有效、可达的答案前缀；后续题目尚未符合长度、数量或数值规则的输入保留在页面，返回该题后可以继续修正，不会在前题触发后题错误。页面明确提示这些未完成输入尚未保存，刷新前应修正；已保存的合规答案可从MongoDB恢复。提交仍由后端完整校验，不放宽数据库中的答案规则。

编辑器记录本地编辑序号。请求返回时若已有新编辑，只更新服务器revision，保留新内容及未保存标记；预览和发布暂停，要求再次保存。填写页面在保存请求进行中禁用答案输入，避免请求内容与用户看到的答案不同。

恢复填写前等待本人草稿查询完成；已有草稿的匿名选项显示其实际isAnonymous并锁定，页面说明继续填写会沿用该设置。账号身份不会因简介页默认勾选值而被错误展示。

## 原答卷修改

首次提交后的主答案保持status=submitted。请求edit创建editDraft，之后保存只改editDraft。修改期间即使用户退出或刷新，已提交统计仍基于原答案。最终确认经过相同的规则、权限、截止和事务检查，再替换主答案、清空editDraft、增加editCount和revision。第一次submittedAt保持，最近提交时间单独存lastSubmittedAt。

不允许修改的模式拒绝edit；允许重复时使用新的clientAttemptId创建新文档，不修改旧答卷。所有路径均通过内部participantKey确认填写者身份，不能凭答卷ID修改别人数据。

## 准入与重试

每次事务尝试重新取当前服务器时间，条件写问卷入口后记录acceptedAt。问卷在准入前关闭或截止则拒绝，已经准入的事务可以稍后完成。与关闭争抢同一问卷文档时，写冲突触发事务重试。

submissionId标识一次确认操作，相同ID与相同规范化载荷返回原结果；相同ID换内容返回409。重复成功请求在问卷关闭后仍可查询到成功凭证。唯一索引阻止同账号不同尝试在禁止重复时同时提交。旧revision保存不能覆盖新数据。

最终提交直接携带当前完整答案，由既有事务一次保存；不先调用草稿保存接口。网络或服务器错误导致结果不确定时，页面保留原答案、revision和submissionId，锁定输入并提供“重试提交”。后续重试即使遇到限流，也继续保留原请求，直到确认成功或用户刷新查询结果。保存草稿的响应丢失时，仅在回读的revision恰好增加一次、答卷仍可编辑且答案与发送内容完全一致时恢复进度，否则保留错误，不能覆盖其他页面的新修改。

## 边界

前端所有题目/选项/规则/尝试/提交ID统一通过uuid.ts生成：存在原生randomUUID时使用原生方法，否则使用getRandomValues构造合法UUID v4，支持普通局域网HTTP。ID格式及提交幂等策略保持不变。分享复制在剪贴板不可用/拒绝时选中链接并提示手动复制，不虚报复制成功。详细复现见browser-compat-audit.md。

第一阶段问卷发布后锁定题目与策略，可以延长截止或关闭；关闭后不重新开启。只支持向后跳转，文本内容不设置条件分支。可以复制新问卷并重新配置。报表聚合以最新成功提交为准，草稿不计；第一阶段保留全部答卷且未提供自动归档删除。
## 二期提交前修复

题库导入、派生并替换的异步结果通过最新草稿引用应用，不能用发起请求时的旧定义覆盖当前编辑；替换保留当前顺序与其他题的入站跳转，原实例已删除/替换则中止写入问卷。复制问卷时题目ID映射用于跳转，选项ID映射逐题构建：题库引用保留原选项ID，独立题生成新ID，两类题不会相互污染。
