## 用户新增策略的重点用例

### 账号提示和注册密码

1. 输入尚未注册的有效用户名及短密码“1”，登录先提示“该用户名尚未注册，请先创建账号”，不误报密码复杂度。
2. 点击创建账号，用户名和returnTo自动保留；注册页逐项显示长度、大写、小写、数字是否满足。
3. 分别输入abc12345、ABC12345、Abcdefgh、Ab1，对应仅提示缺大写、缺小写、缺数字、少于8字符。
4. 输入abcdefgh，同时提示缺大写和数字；所有条件满足后可注册。
5. 绕过页面直接调用注册API，仍返回422和具体缺少项，账号未写入，响应不包含密码。
6. 已有用户名换大小写注册仍返回409；登录已存在账号且密码错误时只提示密码错误。
7. 模拟旧账号不含大写的历史密码，验证仍可登录；新密码规则不锁住旧账号。

实际自动化入口为tests/auth.test.ts与tests/e2e/auth.spec.ts，覆盖共享规则、HTTP接口、注册链接、动态清单和移动宽度。

### 单次填写允许修改

1. 创建禁止重复、允许修改的问卷，数字题首次提交2。
2. 记录答卷ID和revision；进入edit，保存修改草稿8。
3. 在确认前读取统计：仍为1份、1人、平均值2。
4. 确认修改：答卷ID相同、editCount=1，统计为1份、1人、平均值8。
5. 发送旧revision的自动保存：返回409且主答案不变。
6. 关闭问卷后尝试进入修改：410。

### 允许重复填写

1. 创建允许重复、关闭原答卷编辑的问卷。
2. 同一账号以不同clientAttemptId分别填写数字10、20。
3. 两次答卷ID不同；统计为2份、1人，数字平均值15。
4. 原答卷编辑接口拒绝，原答卷不被第二次填写覆盖。

## 并发与隐私

- 同一账号两个填写尝试同时提交：仅一份成功，另一份409，数据库中submitted数为1。
- 同一次确认的并发重试：均返回同一份成功答卷，不重复写入。
- 10个账号同时提交：全部成功，统计10份、10人。
- 关闭与提交并发：只允许提交先准入成功或先关闭后拒绝的合法结果；不存在半提交。
- 匿名答卷创建者读取：respondentId=null，响应不含participantKey、clientAttemptId和editDraft。
- 实名策略下强行匿名：422；本人以实名提交后数据库保留账号ObjectId。
- 过期会话仍未被TTL清理：鉴权401；非法Origin或CSRF：403。
- 数据库直接写错误BSON或匿名账号身份：validator拒绝，错误码121。
