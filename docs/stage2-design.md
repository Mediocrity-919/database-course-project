# 第二阶段需求与实施设计

依据：本地《大作业一：需求变更.docx》。基线为main/cd7e6d8，在v2增量扩展。

| 需求 | 实现方案 |
| --- | --- |
| 常用题复用 | 独立题目系列与不可变版本；编辑器从题库导入固定版本 |
| 用户间共享 | 按用户名授权使用系列所有版本；只有作者可修改系列及共享名单 |
| 发布后不受改题影响 | 问卷继续嵌入题目快照，记录source系列/版本ID，不动态读取最新题目 |
| 修改历史与恢复 | 版本记录parentVersionId；恢复旧版生成新版本并记录restoredFromVersionId |
| 多版本并存 | 任意旧版本可派生新版本；问卷可选择任何可访问版本 |
| 使用情况 | 从草稿及发布快照查询引用，可按单版本或整道题（全部版本）查看，并标明每份问卷用的是哪一版；本人问卷展示详情，其他问卷按授权展示名称。编辑器内修改引用题时由用户选择“保存为题库新版本并替换”或“解除关联只改本问卷” |
| 题库管理 | 新增题库，编辑名称说明，题目系列可归入多个本人题库；题库显示系列最新版本 |
| 跨问卷统计 | 默认按具体版本汇总；切换“全部版本合计”后汇总同一道题的同题型版本，并逐版本拆分份数。选项ID与文字均相同时合并，改名选项单列；支持数字均值/范围/分布、本人文本原文 |

## 数据结构

保留users、sessions、surveys、survey_versions、responses及其现有字段和索引；增加question_banks、question_families、question_versions。新集合分别使用schemaVersion=1（其自身结构版本，不是项目阶段）。

- question_banks：ownerId、name、description、revision、创建/更新时间。
- question_families：ownerId、latestVersionId、versionCount、revision、sharedWithUserIds、bankIds、创建/更新时间。
- question_versions：familyId、versionNumber、parentVersionId、restoredFromVersionId、content、createdBy、createdAt。content为一期题目结构；独立题目只保存题干、选项与校验，跳转属于具体问卷，不保存跨问卷目标。
- 问卷题目增加可选source={familyId,versionId}。旧问卷缺此字段仍合法，不自动关联或改写旧答案。导入时生成新的题目实例UUID，保留版本选项ID用于统计，问卷内跳转独立配置。修改题干、选项、必答或校验须在题库创建版本，或显式脱离题库生成新独立题目；服务器核对来源快照，拒绝伪造。
- settings增加可选shareLibraryStatistics，默认false。开启后允许所用题目的作者查看问卷名称与汇总统计，不包含账号或文本原文。

## 一致性与权限

题目内容只有新增接口，无覆盖/删除版本接口。新增版本及最新指针在事务中更新，revision条件防止并发覆盖，familyId+versionNumber唯一。恢复不是回退数据库指针，而是生成新版本。使用题目只复制快照，授权撤销不会破坏已保存问卷，但不能再次导入；共享接收者另存为自己的新系列，可记录来源版本，不获得原系列修改权。

题库ownerId索引，系列ownerId/updatedAt和sharedWithUserIds索引，题目版本familyId/versionNumber唯一索引；问卷草稿及发布快照的source.versionId建立多键索引以查询引用。归属、跨集合引用、动态规则由后端检查；MongoDB validator约束字段和类型。

## 统计口径

默认仅统计当前用户拥有的问卷；题目作者还可统计明确开启分享汇总的问卷。共享题目不默认授予答案查看权。使用情况中其他未授权问卷只显示匿名化占位及数量，不泄露标题。选择一个确切版本跨问卷统计；每份答卷对该版本最多回答一次（同卷不重复导入同版本）。分母为实际有效答案，草稿/editDraft不计；participantKey在问卷间不可比，不宣称跨卷去重人数。文本明细仅来自本人问卷并分页，外部问卷只贡献汇总数。

## 兼容与实施顺序

1. 先执行scripts/backup.ts，以一致性读取导出开发库Extended JSON至忽略的.local/backups，保留旧记录及.env。备份不等同已完成恢复演练。
2. 增加可选字段和三个集合、校验器、索引；原五集合不做破坏性迁移，旧快照与答卷不改写。
3. 实现题库、共享、版本、恢复、使用查询和统计API；补足伪造来源校验。
4. 前端加入题库页面、版本历史、共享、引用和统计；编辑器支持导入及保存常用题，延续一期布局。
5. 在questionnaire_test运行原94项单元/API与19条浏览器回归，再增加二期API与浏览器流程，构建后HTTP冒烟。
6. 更新文档与实测结果；保持网站运行供用户验收。原需求和项目报告不提交GitHub。

## 实施结果与取舍

上述数据库、API、题库页面及编辑器入口均已实现，后续检查补充了跨版本统计和编辑器并发操作等回归。最新执行结果及证据见test-results.md；逐项人工操作见stage2-audit.md。

所有题库版本一经保存即不可变，不区分是否已发布；这是对“改题生成新题”和历史追踪的统一实现。仅需本卷变化时，用户可解除关联生成独立新题。暂不提供题库/历史版本删除及自动批量升级问卷。跨版本汇总需主动切换范围；题意或数字单位改变时应使用单版本统计。

旧结构到v2为向前兼容；main并不理解新字段，切分支不能当数据库回滚。两期并行展示需要隔离数据库。题库/引用清单尚未分页，版本、题目列表及文本答案已分页；当前按课程规模设计，未做大规模压测、恢复演练或公网部署。

## 2026-10-28补充修改

对照需求原文复核后发现三处需要补强，均为在v2上增量修改，不改变已有集合结构、不迁移旧数据：

1. **需求8只能看单个版本**。原文例子是“你的年龄”在很多问卷里使用、要看总体年龄分布；若部分问卷已换用v2，原实现会把结果拆散。现stats/usage增加scope=family：以所选版本为基准合计同系列同题型版本，逐版本列出份数，题型不同的版本单列不合并。默认仍为单版本，原接口行为与测试不变。
2. **需求6“修改时可以决定是否创建新版本”缺少就地入口**。原来必须离开编辑器到题库页派生，再回来替换。现在编辑器内的引用题提供两个并列选项：“修改内容并保存为题库新版本”（作者追加版本；共享接收者另存为自己的系列并记录来源）后自动替换本题；或“解除关联并编辑副本”只改本问卷。题库页查看使用情况时可按整道题列出各问卷所用版本，帮助判断影响面。
3. **数据库验收与约束**。question_versions的validator收紧为禁止source、order=1、无跳转规则；跨卷统计的首个$match补上surveyId以命中统计索引；新增只读的`npm run db:verify`覆盖集合、validator、索引、全部文档、版本链、引用和升级前备份比对，以及一键验收脚本`npm run accept`。

继续保持的取舍：所有题库版本不可变，“不建新版本”的修改通过解除关联实现；不提供删除版本、自动批量升级问卷或按标签猜测合并选项。
