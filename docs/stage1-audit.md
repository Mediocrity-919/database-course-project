### B. 文本长度口径不一致——已修复并回归

计划和业务校验按Unicode码点计算字符数；实际输入框的原生maxLength及答案API的z.string().max(2000)按UTF-16长度限制。

- 将文本题设为最少2、最多2字符，在Chrome输入“😀😀”：输入框只保留1个表情，随后提示“请输入2～2个字符”，而业务规则认为原输入恰好2字符、应当合法。
- 将上限设为2000字符，提交1001个“😀”：业务函数接受1001字符，但API返回422 INPUT_INVALID，因为其UTF-16长度为2002。

修复涉及apps/web/src/components/QuestionInput.tsx及packages/shared/src/domain.ts。共享normalizeTextAnswer/textAnswerLength统一规范化和码点计数，输入框移除原生maxLength；接口与业务规则采用相同口径。新增7项单元/API、3条浏览器回归全部通过，实际数据库2000码点可存、2001码点拒绝，无需迁移。上述例子为修复前复现过程。

复现脚本与结果保存在.local/qa/stage1-requirements-audit.ts及stage1-requirements-results.json。脚本仅向questionnaire_test写入测试数据；对开发库只读取集合/索引元数据。

## 3. 数据库专项核对

| 要求/设计点                             | 核查结论                                                                            |
| --------------------------------------- | ----------------------------------------------------------------------------------- |
| 使用MongoDB，不用关系数据库             | 满足；官方MongoDB驱动，未发现关系库业务存储                                         |
| 不使用现成问卷系统框架                  | 满足；自建定义、校验、跳转、提交和统计逻辑，通用React/Express/Zod不属于现成问卷系统 |
