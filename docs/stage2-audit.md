# 第二阶段验收清单

需求来源为本地《大作业一：需求变更.docx》，基线main/cd7e6d8，改动位于v2。数据库细节见database-design.md，实际测试记录见test-results.md。当前八项需求均有对应页面、服务接口和自动化用例；下列步骤供人工复验。

| 原需求 | 入口/实现 | 人工操作及预期 |
| --- | --- | --- |
| 1 常用题复用 | 我的题库、从题库选题 | 新建数字题“年龄”，两份问卷分别选v1；题目实例不同但绑定同一版本 |
| 2 跨用户共享 | 共享与题库归属 | 填另一个已注册用户名，双方均可导入；对方不能修改原系列 |
| 3 不改历史 | 不可变题目版本+发布快照 | 发布并填写问卷A后创建v2，A原题及答案保持，不能直接覆盖v1 |
| 4 历史/恢复 | 版本历史及查看内容与来源 | 查看父版本；恢复v1生成新版本，不删除v2 |
| 5 多版本并存 | 任意历史版“创建新版本” | 从v1再派生分支，问卷B可选新版、A继续用旧版 |
| 6 使用查询 | 查看使用与统计（仅此版本/全部版本合计）；编辑器内两种修改方式 | 看本人引用问卷并进入管理，整道题模式标明各问卷用的版本；外部未授权名称隐藏。编辑器中可选“保存为题库新版本并替换”或“解除关联只改本问卷”，均不影响已有问卷 |
| 7 题库管理 | 题库名称/说明、归属复选框、筛选 | 新建改名、加入移除题目、题库选题；创建新版本后仍归原题库 |
| 8 跨卷统计 | 统计区“仅此版本”/“全部版本合计” | 两卷用v1分别回答20与40：v1有效回答2份、平均30。另一卷用v2回答30后，“仅此版本”v1仍2份，“全部版本合计”为3份、平均30，并显示v1：2份、v2：1份 |

## 一键自动验收（先做）

1. 确认MongoDB副本集已启动：`npm.cmd run db:start`（已在运行可跳过）。
2. 在项目根目录运行：`powershell -NoProfile -ExecutionPolicy Bypass -File scripts\acceptance.ps1`（等同`npm.cmd run accept`）。
3. 脚本依次执行：环境与Git状态 → 开发库`db:backup` → `db:init`（只增补validator/索引）→ 开发库`db:verify --baseline latest` → 单元/API测试 → 测试库`db:verify --test` → 构建 → HTTP冒烟 → 浏览器测试。任何一步失败立即停止后续步骤，打印已执行步骤的SUMMARY并以非零退出；备份失败不会初始化开发库，构建失败不会测试旧产物。
4. 结果：`.local/qa/acceptance-时间.log`；JSON报告`db-verify-dev-*.json`、`db-verify-test-*.json`、`unit-api-*.json`、`e2e-*.json`。全部PASS才算自动验收通过。

## 建议验收顺序

1. 用原账号登录；已有一期问卷仍可查看与操作。打开“我的题库”，当前开发库没有自动注入测试题，按需要创建自己的题库。
2. 建立“基本资料”题库和“年龄（周岁）”数字题，配置0～120及整数；保存后勾选归属并保存。
3. 新建两份问卷，从题库选择同一版本。导入的核心内容锁定，跳转仍可设置；发布后各填写一次20和40，查看题库统计。
4. 创建v2，修改题目范围或标题。查看v1的问卷和答案保持不变；新草稿可以选v2。已发布问卷需要复制为新草稿后改用新版本。
5. 从v1派生另一版，查看父链；恢复v1得到新版本，历史仍保留。草稿中替换版本会提示重置本题跳转，其他题的入站跳转保留。
   - 在一份草稿中选中题库题，点“修改内容并保存为题库新版本”，改范围后确认：本题换成新版本并保持锁定；题库中多一个版本，旧问卷不变。另点“解除关联并编辑副本”可只改本问卷，题库不新增版本。
   - 在题库页选v1，点“全部版本合计”：份数为各版本之和，并逐版本列出；切回“仅此版本”恢复单版本结果。
6. 注册另一账号，在原作者页共享给它；另一个浏览器会话验证选用与另存。撤销后新导入失败，但先保存的问卷继续可用。
7. 其他用户的问卷默认不贡献原作者统计；在发布前主动勾选汇总授权后才贡献。外部文本原文、账号及完整答卷不共享。
8. 手机打开同局域网地址，通过顶部“我的题库”操作选题、版本替换与独立副本编辑，检查无横向溢出、保存刷新仍在。

## 设计边界

- 所有入库版本不可变（包括未用于问卷的版本）；修改始终追加版本，避免引用状态判断与并发修改冲突。若只改本问卷可解除关联生成新独立题。
- 单卷不能重复同一题目版本；不同版本可共存。默认按版本统计，可主动切换同题型版本合计；选项ID与文字均相同时合并，改名选项分别显示。题意/单位变化需用单版本统计。跨卷按有效回答份数计算，不冒充去重人数。
- 题库管理支持创建、改名、说明、归属增删及版本选择；没有删除历史版本或题库的入口，避免悬空引用。
- 共享是使用权限；问卷统计授权另设，默认关闭。使用清单对外部未授权名称脱敏；当前题库列表/引用清单未分页，适合课程规模。
- 发布后的内容和授权设置冻结。更换内容/统计授权需复制为新问卷，不回改历史快照。
- 本轮没有公网部署、微信真机操作或数据库恢复演练；本地备份、兼容性比对及Chrome普通HTTP自动化均与这些事项区分。
